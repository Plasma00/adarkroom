# 战斗弹框性能与半径45方案解析

用户报告移动恢复流畅但攻击框出现卡顿，并要求按坐标半径45（确认完整91×91）计算不同距离的地点数期望，不做随机模拟。

性能诊断使用隔离Edge测试存档、61×61显示和4倍CPU降速，每种干预开关真实战斗框6次。记录同步启动、观察器微任务及强制布局耗时，并单列下一动画帧回调间隔。首次基线中位82ms，复测67.9ms；禁用整棵内容树inert可降到21.6ms，说明主要额外开销在数千地图节点的样式与交互状态重算。该禁用只用于诊断，未作为最终交互方案。

实现：仅给实际操作区设置inert，保留背景遮罩与键盘锁，给World.click补充弹窗/锁检查；用aria-hidden隐藏背景辅助技术内容，弹窗声明dialog/aria-modal并接收焦点，关闭恢复原焦点。动画改用浏览器原生透明度动画，旧浏览器保留jQuery回退。桌面预留页面滚动条位置，手机不额外消耗15像素宽度。优化后中位启动耗时29.8ms，下一帧回调间隔80.2ms；这是同一模拟慢设备下的渲染指标，不是对用户机器FPS的测量。

解析计算读取当前地点定义，不调用World.init或generateMap，不进行抽样。对每种地点按原提议分布计算边界接受率 q(d)，再归一化得到每个距离及区间的期望，忽略已有地标占位及500次重试兜底的相关性，报告明确注明该近似。输出 doc/map-radius45-expectations.md、CSV及landmark-expectations.json。首周目总数136；91×91地图在61…90距离处有1860格没有初始地点，现有常规后期敌人也止于60。地图半径和地点配置尚未修改，供用户评估方案。

新增桌面/手机双场景回归：重复开启与关闭战斗、焦点进入与恢复、背景控件不可交互、地图程序触发和键盘移动受锁保护、攻击仍扣除敌方生命。首轮断言未等待100ms战斗命中回调，已改为等待真实HP变化；滚动条留白改为仅桌面以保持手机原有宽度。最终24项逻辑测试及内容校验通过。全量浏览器检查后，针对上述修正重跑战斗弹框、布局和手机的14项用例，全部通过；其余20项已在全量检查通过。查看手机战斗框截图，标题、战斗操作和背后地图显示正常。
