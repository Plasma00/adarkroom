# 探险移动性能与移除训练说明

用户要求删除探险页“专长训练”，并诊断探索卡顿。已删除 Path.updateTraining 及调用、专用CSS，保留专长列表和全部解锁/伤害规则。

根因：上一次独立网格排版引入了每格DOM节点，但 drawMap 每一步仍用整段HTML替换地图。在61×61地图中，24次移动累计添加/删除各90744个直接节点；另有其内部文本和提示节点、图例重建及相应的样式计算和布局开销。卡顿存在可重复的前端原因。

修改：网格节点和每格上次输出缓存在 World 对象中；显示边长或DOM元素变化时重建，其余时候只写入内容变化的格子。每次仍比较当前状态，避免缓存遗漏死亡回退、访问标记或前哨使用。图例按已知类型/名称签名更新，地图范围标签和CSS变量只在重建时更新。缓存不进入 World.state 或存档。

性能证据：`tools/profile-world-render.js` 在隔离Edge浏览器中导入既有测试存档，模拟4倍CPU降速，每种地图执行24次往返移动，计入同步渲染及强制布局，排除随机遭遇、声音和生存事件。原始结果见 before.json / after.json。30格地图中位耗时61.4→5.0ms，95分位80.4→17.0ms；61格地图中位200.2→13.5ms，95分位276.3→17.1ms。61格的24次移动仅添加/删除各48个节点，约每步两格；这些是该环境的渲染耗时，不是用户设备整体帧率的测量。

回归涵盖：无变化时不发生地图DOM变更、移动时复用全部网格及图例且仅改变两格；已访问地点、用过的前哨、迷雾回退及图例遗忘；地图扩大、DOM重建；探险页不再包含训练说明。最终 `npm test` 24项逻辑测试及内容校验通过，`npx playwright test` 全部32项浏览器测试通过。
