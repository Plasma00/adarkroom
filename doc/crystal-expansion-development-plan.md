# 晶格远征扩展开发规格

> 初始开发规格：核心扩展已经实现，后续地图和配方已调整。当前完成情况、测试与待办见 [项目当前状态](project-status.md)，实现说明见 [crystal-expansion-implementation.md](crystal-expansion-implementation.md)。

状态：设计草案，可作为后续开发窗口的实施依据。
基线：`main` 分支当前网页版本，游戏存档版本为 1.3。
范围：世界坐标重构、流浪者舰船、人类工业遗址、晶体经济、飞船航向晶格、人口扩展，以及现有后期战斗的兼容修正。

## 1. 目标与设计原则

本扩展延续原作从木材、皮革和食物，发展到铁、煤、硫磺、钢铁，再接触流浪者技术的演进过程。新增内容应继续使用已有资源和玩法约束，避免出现只服务于单个配方的孤立材料。

本扩展的叙事前提是：人类遗迹保存了采掘、切割、刻蚀和精密装配能力；流浪者舰船保存了人类无法自行创造的晶格结构。玩家必须结合两个文明留下的技术，才能让旧飞船重新认识天空。

晶体在世界观中承担类似半导体基材的作用，但玩家文本不直接使用“半导体”“计算机”“CPU”“软件”或“操作系统”等名称。优先使用 `crystal`、`lattice`、`guidance`、`memory`、`light`、`dark`、`aligned` 和 `awake` 等词。项目内部可将星球视为地球，但玩家文本继续保持原作的含蓄，不主动写明 Earth，除非后续剧情另有决定。

必须保留现有普通结局、舰队信标扩展结局、残破战舰三翼与指挥甲板首领。新增修复条件不得把击败“不朽流浪者”变成普通通关的必要条件。

## 2. 已确认需求与建议默认值

### 2.1 已确认需求

- 村庄的世界坐标改为原点 `(0, 0)`。
- 世界坐标范围为 `x,y ∈ [-r,r]`，初始 `r = 30`，边界包含 `-30` 和 `30`。
- 初始地图仍为 `61 × 61 = 3721` 格；本阶段完成坐标重构和内容扩展能力，不立即把 `r` 提高到40或更大。
- 现有残破战舰代表流浪者，并增加若干流浪者舰船。
- 增加代表人类文明的工业遗址。
- 晶体具有类似半导体的控制、感应和信号作用。
- 飞船除舰体和推进器外，还需要晶体相关的内部控制结构才能起飞；玩家界面称其为“航向晶格”或简称“晶格”。
- 晶格修复必须同时依赖流浪者舰船和人类工业遗址提供的资源或能力。
- 后期村庄人口可小幅提高，以支持新增工业岗位。

### 2.2 建议默认值

- 新增两艘流浪者舰船，加上现有残破战舰，共三处主要流浪者舰船遗迹。
- 新增三类人类工业遗址：晶体厂、化学工场、精密装配厂。
- 现有20间小屋和80人口上限保持不变；工业扩展后解锁两座工棚，每座增加10人口，最终上限100。
- 航向晶格分三段修复，状态值为 `0..3`。
- 新增普通资源 `crystal` 和稀有任务资源 `lattice shard`；`guidance lattice` 是飞船状态，不作为可堆叠库存物品。
- 第一轮扩展复用现有能量刃、等离子步枪、干扰器和动能护甲。人类线圈枪作为后续可选内容，不列入核心交付条件。

以上“建议默认值”可在开发前调整；“已确认需求”应视为实现约束。

## 3. 世界坐标重构

### 3.1 坐标语义

重构后所有游戏逻辑使用世界坐标：

```text
village = (0, 0)
x ∈ [-30, 30]
y ∈ [-30, 30]
north = (0, -1)
south = (0, 1)
west  = (-1, 0)
east  = (1, 0)
distance((x1,y1),(x2,y2)) = |x1-x2| + |y1-y2|
```

`World.VILLAGE_POS` 必须改为 `[0, 0]`，`World.curPos`、地标坐标、点击移动、罗盘方向、道路绘制和距离判断都以世界坐标表示。边界判断统一使用 `World.isInBounds(x, y)`，禁止业务代码继续直接比较 `0` 与 `World.RADIUS * 2`。

### 3.2 地图存储

为降低重构风险，第一阶段保留二维数组存档格式。负坐标通过唯一的转换层映射到数组下标：

```javascript
World.toIndex = n => n + World.RADIUS;
World.toCoord = i => i - World.RADIUS;
World.isInBounds = (x, y) =>
  x >= -World.RADIUS && x <= World.RADIUS &&
  y >= -World.RADIUS && y <= World.RADIUS;
```

必须提供并统一使用以下访问器：

```javascript
World.getTile(map, x, y)
World.setTile(map, x, y, value)
World.getMask(mask, x, y)
World.setMask(mask, x, y, value)
```

数组下标属于存储实现细节，不得从上述访问器泄漏回玩法代码。以后把 `r` 调整为40时，应只影响地图尺寸、生成配置和内容分布，不再要求第二次坐标语义重构。

### 3.3 必须改造的世界函数

- `newMask`、`lightMap`、`uncoverMap`；
- `generateMap`、`chooseTile`、`placeLandmark`、`mapSearch`；
- `moveNorth/South/East/West`、`move`、`click`；
- `drawMap`、`drawRoad`、`markVisited`、`outpostUsed`；
- `getDistance`、`compassDir`、所有按距离触发的危险和事件判断；
- 旧存档迁移、测试地图和地图全开逻辑。

`placeLandmark` 应返回逻辑坐标，并改用候选地形集合随机抽取，或者至少设置有限重试次数。当前无限循环在增加地标密度后存在卡死风险。

### 3.4 存档迁移

提升 `Engine.VERSION`。迁移后的 `game.world` 至少保存：

```javascript
{
  radius: 30,
  map: [...],
  mask: [...]
}
```

旧版61×61数组无需搬动物理元素；迁移只需写入 `radius: 30`，并确保以后从数组中取得的位置转换为世界坐标。任何旧版位置或地标坐标若采用数组下标，必须减去30。迁移应幂等，重复加载不会再次偏移坐标。

## 4. 地图内容与流程

### 4.1 距离带

在 `r = 30` 的第一版中，地标继续按距村庄的曼哈顿距离分层：

| 距离 | 内容定位 |
|---:|---|
| 0–9 | 原作生存、旧屋、洞穴、铁矿 |
| 10–19 | 小镇、煤矿、早期人类工业痕迹 |
| 20–26 | 硫磺矿、废城、晶体厂、化学工场、侦察舰 |
| 27–30 | 坠毁飞船、残破战舰、运输舰、精密装配厂 |

新增地标在地图生成时必须保证可达且互不覆盖。关键通关物品不得由纯随机概率决定；随机只能影响路线、敌人、额外战利品和支线文本。

### 4.2 流浪者舰船

1. **残破战舰（现有）**：保留工程、医疗、军事和指挥甲板。初次主线探索获得制造器设备和第一块 `lattice shard`。指挥甲板首领仍提供 `fleet beacon`，属于高难度可选支线。
2. **坠毁侦察舰（新增）**：规模较小，以失真的航图、传感器和路线选择为主。提供第二块 `lattice shard`；完成后揭示部分未探索地标或提供一次大范围地图照明。
3. **掩埋运输舰（新增）**：以货舱、电力分配和无人机为主。提供第三块 `lattice shard`，并给予能量电池、少量外星合金或货运相关奖励。玩家可把有限电力导向不同区域，选择影响额外战利品，但不能失去必要晶格碎片。

三艘舰船使用不同的玩法节奏。残破战舰偏战斗和剧情，侦察舰偏探索与判断，运输舰偏资源取舍。避免复制相同的长走廊和连续战斗。

### 4.3 人类工业遗址

1. **废弃晶体厂**：发现被切割成薄片的晶体，首次提供少量 `crystal`；清理后解锁村庄的晶体生产能力。
2. **化学工场**：展示腐蚀槽、过滤设备和硫化物处理设施；完成后设置 `features.industry.etching = true`，允许制造器修复晶格。硫磺由此继续参与后期经济。
3. **精密装配厂**：保留钢制框架和细小连接结构；完成后解锁人口扩展建筑 `bunkhouse`，并允许飞船安装完整晶格。

人类遗迹不能直接制造流浪者晶格。环境文本应表现为人类能够复制形状，但无法理解其中保存的结构。例如：

```text
thin crystal sheets rest beneath shattered glass.
each is cut with impossible precision.
human hands copied the pattern. poorly.
```

舰船内对应文本可使用：

```text
pale crystal runs behind the walls.
the broken lines still carry light.
every fragment points the same way.
```

## 5. 资源与经济

### 5.1 资源职责

| 资源 | 类型 | 来源 | 主要消耗 |
|---|---|---|---|
| `steel` | 现有工业材料 | 钢铁工人 | 装配框架、武器、住房 |
| `sulphur` | 现有矿物 | 硫磺矿工 | 子弹、晶体刻蚀 |
| `energy cell` | 现有能源载体 | 舰船和机械敌人 | 能量武器、晶格启动 |
| `alien alloy` | 现有稀有结构材料 | 钻孔、战舰、机械敌人 | 飞船、流浪者装备 |
| `crystal` | 新增普通后期资源 | 人类晶体厂及生产岗位 | 聚焦、感应、晶格修复 |
| `lattice shard` | 新增稀有任务资源 | 三艘流浪者舰船 | 航向晶格三段修复 |

晶体不直接生产能量电池；能量电池保持“能源”身份，晶体保持“信号与控制材料”身份。外星合金继续是稀有探索资源，不开放无限矿工生产。

### 5.2 晶体生产

清理废弃晶体厂后解锁晶体岗位。建议初始生产率：每名晶体工每30秒消耗1份腌肉并产出1份晶体。最终数值通过试玩调整。

生产来源应进入现有 `$SM.setIncome()` / `$SM.collectIncome()` 系统，不建立第二套离线或实时结算器。岗位名称在定稿时从 `crystal worker`、`crystal cutter` 或更符合原作语气的名称中选择一个，并同步所有语言资源。

### 5.3 现有制造器配方接入晶体

现有后期配方只消耗1～2个外星合金，资源层过于单薄。建议方向如下；具体数量属于平衡参数：

| 装备 | 建议材料结构 |
|---|---|
| 能量刃 | 外星合金＋晶体 |
| 等离子步枪 | 外星合金＋晶体＋少量能量电池用于校准 |
| 干扰器 | 外星合金＋较多晶体 |
| 动能护甲 | 外星合金＋晶体 |
| 发光石 | 晶体＋少量外星合金 |
| 流体回收器 | 外星合金＋晶体＋钢 |
| 货运无人机 | 外星合金＋钢＋能量电池 |

## 6. 飞船航向晶格

### 6.1 状态与界面

飞船初始化状态扩展为：

```javascript
game.spaceShip = {
  hull: 0,
  thrusters: 1,
  lattice: 0
};
```

`lattice` 取值为0、1、2、3。玩家界面不显示 `0/3`，而显示状态文字：

| 值 | 显示 |
|---:|---|
| 0 | `dark` |
| 1 | `fractured` |
| 2 | `aligned` |
| 3 | `awake` |

修复完成文本：

```text
light moves through the crystal.
the ship remembers the sky.
```

### 6.2 修复成本

航向晶格分三次修复。每次建议消耗：

```text
1 lattice shard
4 crystal
10 steel
20 sulphur
3 energy cell
1 alien alloy
```

总成本为3块晶格碎片、12晶体、30钢、60硫磺、9能量电池和3外星合金。该配方确保原作钢铁与硫磺工业在最终阶段仍然有用。数值须通过实际通关时间和库存曲线调整。

晶格修复按钮位于飞船界面，实际加工要求 `features.industry.etching`，第三段安装还要求完成精密装配厂。资源扣除必须原子化：任意一种材料不足时不改变库存和晶格状态。

### 6.3 起飞条件

`Ship.checkLiftOff()` 同时检查：

```text
hull > 0
lattice === 3
```

晶格未完成时显示：

```text
the engines answer.
the ship does not know where to go.
```

推进器继续决定太空阶段的操纵能力，舰队信标继续只影响扩展结局。坠毁后晶格保持完成状态，不要求重复收集任务物品。

## 7. 人口与住房

当前上限为20间小屋，每间4人，总人口80。早期规则保持不变：

```text
hut maximum = 20
hut capacity = 4
early maximum population = 80
```

完成精密装配厂后解锁两座 `bunkhouse`，每座容纳10人：

```javascript
maxPopulation = huts * 4 + bunkhouses * 10;
```

最终人口上限为100。工棚使用木材、钢和皮革建造，不消耗晶体。建议成本随数量递增，保证它是后期扩展而不是廉价人口来源。

新增住房后必须重写 `destroyHuts()` 中“所有人口都按每间4人分布”的假设。住房被毁、人口死亡、岗位回退和采集者数量必须保持非负；任何时刻都应满足：

```text
assigned workers <= population <= housing capacity
```

## 8. 后期武器与防御兼容审查

当前版本已经包含能量刃、等离子步枪、干扰器、动能护甲、护盾、`hypo`、`stim` 以及敌人的护盾、狂暴、冥想、能量强化、毒性和死亡爆炸。第一轮扩展优先让这些系统稳定并接入晶体配方。

开发前必须修复以下基线问题：

1. `Events.useStim()` 当前直接设置 `boost`，没有调用带失效计时的 `Events.setStatus()`；加速可能永久持续。
2. `stim` 使用时没有扣除 `Path.outfit.stim`。
3. `createUseHypoButton()` 的数量判断方向错误，拥有物品时会先禁用按钮；治疗按钮刷新也必须同时检查生命值和库存。
4. 当前护盾把一次来袭伤害转换为等量治疗。核心设计改为“阻挡一次伤害后破裂”，不产生治疗；若保留吸收转化机制，必须另行命名并明确展示。
5. `Fabricator.fabricate()` 使用 `Math.min(0, currentCount)` 检查最大数量，导致内部上限保护失效；应使用实际非负数量。
6. 机械四足敌人的 `loot` 对象重复声明 `alien alloy` 键，前一个掉落配置会被后一个覆盖。
7. 战斗结束、死亡和事件切换时必须清理敌方攻击、持续伤害、特殊状态和爆炸计时器。

建议保留动能护甲的高生命值，并让主动护盾消耗1个能量电池、冷却10～12秒、阻挡一击。是否把主动护盾拆成独立的“晶格屏障”蓝图属于平衡决定，不是第一阶段硬要求。

可选的人类后期武器为 `coilgun`：使用钢、晶体和能量电池，射速慢，作用是破坏护盾或机械防御。它不得仅以更高每秒伤害取代等离子步枪；在核心战斗修复与平衡完成前暂不实施。

## 9. 评分与周目继承

- `crystal` 可以加入本局资产分，建议初始每单位5分，防止可再生产资源过度刷分。
- `lattice shard` 是通关任务资源，不进入普通评分表；剩余任务碎片也不应通过刷取产生分数。
- `guidance lattice` 是固定通关条件，不额外计分。
- `crystal`、`lattice shard`、晶格状态和工业解锁不进行周目继承，与外星合金一样要求每一周目重新完成后期推进。
- 现有 `Prestige.storesMap` 和 `Score` 的平行数组应改成按物品ID配置权重，避免新增物品导致下标错位。

## 11. 建议实施顺序

### 阶段一：稳定基线

修复 `stim`、`hypo`、护盾、制造上限、重复掉落键和战斗计时器。完成针对现有残破战舰的回归测试。

### 阶段二：坐标等价重构

在 `r = 30` 下把村庄改为 `(0,0)`，加入坐标访问器并迁移所有世界函数。此阶段不增加地标，不调整原有概率和距离，确保重构前后玩法等价。

### 阶段三：资源与人口

加入 `crystal`、`lattice shard`、工业特性状态、晶体生产岗位、工棚和100人口上限。同步库存、负重、评分和翻译。

### 阶段四：人类工业遗址

实现晶体厂、化学工场和精密装配厂，验证三个解锁状态可以按任意发现顺序安全保存和恢复。

### 阶段五：流浪者舰船

在现有残破战舰中加入第一块晶格碎片，再实现侦察舰和运输舰。关键碎片保证可取得，额外奖励允许分支和随机。

### 阶段六：飞船与结局

实现晶格三段修复、界面状态和起飞门槛。验证普通结局、舰队信标扩展结局和坠毁重试均正常。

### 阶段七：平衡与内容校验

根据实际通关时间调整地标距离、晶体产量和配方。完善所有语言的回退行为、评分、音频缺失回退和地图生成校验。

## 12. 验收标准

### 12.1 坐标与地图

- `World.VILLAGE_POS` 和新游戏起点均为 `[0,0]`。
- 玩家可以到达 `(-30,-30)`、`(-30,30)`、`(30,-30)` 和 `(30,30)`，不能越过边界。
- `getDistance([0,0],[30,30])` 返回60。
- 地图渲染仍为61行、每行61格；玩家、迷雾、道路和工具提示位置正确。
- 所有生成地标位于边界内、覆盖合法地形，关键地标数量满足配置。
- 1.3旧存档加载后地图、已访问状态、矿井、飞船和残破战舰进度不丢失。

### 12.2 资源与人口

- 工业遗址解锁前人口上限为80；两座工棚完成后为100。
- 人口、已分配工人和住房损失在任何事件后都不出现负值或超额分配。
- 晶体进入现有收入结算、库存显示、出行回收和存档系统。
- 外星合金不可通过普通岗位无限生产。

### 12.3 舰船与通关

- 三块必要晶格碎片均有确定来源，任何随机分支都不会造成死档。
- 未完成工业能力或材料不足时，修复操作不扣除任何资源。
- `hull > 0` 但 `lattice < 3` 时无法起飞，并显示晶格相关文本。
- `hull > 0` 且 `lattice === 3` 时可以进入现有太空阶段。
- 坠毁后无需再次修复晶格；成功飞行后的两种结局保持原有条件。

### 12.4 战斗

- `stim` 每次消耗一件，只持续3秒，并在持续期间将攻击冷却减半。
- `hypo` 仅在库存大于0且玩家未满生命时可用，每次恢复30生命并扣除一件。
- 护盾阻挡一击后消失，不增加生命值。
- 干扰器仍眩晕4秒；能量刃、激光步枪和等离子步枪保持各自弹药规则。
- 战斗结束后不存在继续伤害玩家的孤立计时器。

## 13. 建议验证工具

项目当前没有正式测试套件。实施时建议增加基于 Node 内置测试运行器的纯逻辑测试，并把坐标转换、边界、距离、住房容量、配方扣除和起飞条件抽成无DOM函数。另增加一个内容校验脚本，检查：

- 地标字符和事件ID唯一；
- 每个地标引用的事件存在；
- 每个配方和掉落引用的物品存在；
- 每个武器引用的弹药和状态存在；
- 所有关键晶格碎片来源可达；
- 英文基础字符串已进入翻译提取流程。

最后进行浏览器端完整流程验证：新游戏、旧存档升级、三处工业遗址、三艘舰船、晶格修复、太空坠毁、普通结局和舰队信标结局。
